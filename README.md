# Desktop CNC Compare

Static website to browse, filter and compare desktop CNC machines. All data lives in this repo as JSON;
GitHub Actions validates it, builds the site and publishes it to GitHub Pages. No framework, no bundler.

## Layout

```
data/
  schema.json            JSON Schema: validation + labels, units, filters, icons for the site
  cnc/<id>.json          one file per machine, file name = machine id
site/                    published as-is to GitHub Pages
  index.html, app.js, style.css   the page: catalog, filters, comparison sheet
  draw.js                to-scale work-envelope drawings (SVG)
  fonts/                 self-hosted IBM Plex Sans + JetBrains Mono (OFL)
  core/core.js           data loading, schema-driven fields, search/filter/sort, URL state
  core/icons.js          Lucide icon subset
  data/                  generated by scripts/build.mjs (git-ignored)
scripts/
  build.mjs              merges data/cnc/*.json -> site/data/machines.json, copies the schema
  test-core.mjs          self-check for core.js
machines.md              backlog of machines to add
```

## Add or update a machine

1. Copy an existing file in `data/cnc/`, name it `<company>_<model>.json` (lowercase, snake_case).
2. Fill in what you know; use `null` for unknown values. Units and allowed values are documented in
   `data/schema.json` (editors with JSON Schema support autocomplete via the `$schema` key).
3. Accessories go into the `accessories` array: `name`, `price`, `image_url`, `description`, `url`.
4. Open a PR. CI rejects files that do not match the schema.

A new field only needs to be added to `data/schema.json`: filters and comparison rows are derived from it
(`title`, `x-unit`, `x-better`, `x-filter`, `x-labels`, `x-icon`).

## Local development

```sh
npx -y ajv-cli@5 validate --spec=draft2020 --strict=false --validate-formats=false -s data/schema.json -d 'data/cnc/*.json'
node scripts/build.mjs && node scripts/test-core.mjs
python3 -m http.server 8000 -d site    # http://localhost:8000
```

## Deployment

One-time setup by a repo admin: Settings -> Pages -> Source: **GitHub Actions**.

After that every push to `main` validates the data, builds, tests and deploys to
`https://<owner>.github.io/<repo>/`. PRs run the same checks without deploying. All URLs in the site are
relative and state lives in the URL hash, so it works under the repo subpath without extra config.
